# Privacy Policy and Data Safety Guide

Each application needs an accurate, publicly accessible privacy policy, including apps designed not to collect personal data.

## Review actual behaviour

Inspect:
- AndroidManifest permissions.
- Runtime permission requests.
- Network access and endpoints.
- Included SDKs and transitive dependencies.
- Crash reporting, analytics, advertising and attribution libraries.
- Backup, export, import and file-sharing behaviour.
- Any data sent to developer-controlled or third-party services.
- Optional online features.

Do not infer data practices from product intent. Verify actual code and dependency behaviour.

## Offline-first disclosures

Where accurate, explain:
- Core features work offline.
- Data is stored locally on the device.
- Whether Android system backup includes app data.
- Whether users can export or back up data manually.
- Whether optional network features send data externally.
- How users can delete local data.

Do not claim "no data collected" if an SDK, backup mechanism or optional feature transmits data within the store's definitions.

## Google Play Data safety

Complete the Data safety form based on the app and all included SDKs. Ensure the form, privacy policy, app behaviour and store listing agree. Reassess whenever features or dependencies change.

## Policy page requirements

Publish a stable HTTPS page that:
- Identifies the app and developer (SuBZeRo).
- Describes collected, processed and shared data accurately.
- Explains local storage and optional network operations.
- Describes retention and deletion.
- Lists relevant third-party services and policies.
- Provides a working contact route.
- Includes an effective date and revision history.

Do not copy a generic "we collect no data" statement into every app. Prepare and verify a separate policy for each product. This guide is not legal advice.
